# ORBIT 0.5.4 — окно потери черновика

## Модель сохранения

- Изменения TextEditingController сразу видны в памяти, но подтверждённой записью считается только завершённая очередь `flush()` в `OrbitAppState`.
- Обычный ввод сохраняется с debounce 450 мс. System Back, lifecycle pause и dispose принудительно выполняют flush последовательной очереди.
- `lastSavedDraft` отделяет подтверждённые байты от текущего ввода. Ошибка записи видна, retry не удаляет текст.

## KIMI_RUN на Android 15 x86_64

`tool/android_draft_kill_window_054.py` вводит уникальные получателя/тему/текст, сразу вызывает `am force-stop` и холодно перезапускает приложение.

| Задержка после последнего ввода | Результат | Поля после relaunch |
|---:|---|---|
| 0 мс | PASS | Все три поля восстановлены |
| 100 мс | PASS | Все три поля восстановлены |
| 250 мс | PASS | Все три поля восстановлены |
| 500 мс | PASS | Все три поля восстановлены |

Исходные результаты: `runtime/draft-kill-windows.json`, `logs/draft-kill-windows.txt`, `android_054_kill_*.png`.

## Граница гарантии

`am force-stop` — это управляемая Android-операция, а не внезапное отключение питания. Lifecycle callback может успеть подтвердить запись. Нельзя обещать сохранение каждого последнего символа при физическом отключении устройства или SIGKILL до начала записи. Debounce уменьшает I/O, Back/pause/dispose сокращают окно, но не устраняют его полностью.
